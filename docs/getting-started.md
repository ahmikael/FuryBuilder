# Getting started

This guide takes you from a fresh checkout to a saved, exported build. It describes the
current Windows beta, not a future release. If a screen or action is not listed here, assume
it is not implemented yet.

To install a packaged Windows beta instead of running a checkout, start with
[Windows installation and updates](install-windows.md); the supported baseline and tested
reference machine are in [Reference](reference.md).

FuryBuilder is a desktop 3D editor for Minecraft Java Edition worlds and structures. It is
not a game client: it does not run Minecraft, simulate redstone or guarantee vanilla world
generation outside the explicit `Vanilla World` mode. The Rust core is the source of truth
for blocks; the viewport is a derived view.

## 1. What you need

- Windows 10 or 11 (64-bit) with the WebView2 runtime (normally preinstalled).
- No Minecraft installation, Java runtime or server JAR is required for `Empty Project`,
  `Flat base`, `Import World` or structure import/export.
- Building from source additionally needs Node.js 26+, pnpm 10+ and Rust stable with the
  MSVC toolchain and Visual Studio Build Tools.

Minecraft assets, Java and the official server JAR are optional additions for realistic
textures and `Vanilla World`. FuryBuilder never bundles Mojang game files. The full
baseline, tested reference machine and unsupported configurations are in
[Reference](reference.md).

## 2. Start the application

From the repository root:

```powershell
pnpm install
pnpm tauri:dev
```

`pnpm dev` alone opens the UI in a browser as a **preview**: it cannot edit, save, export or
run MCP, because the Rust backend is not attached. Use `pnpm tauri:dev` for real work.

Useful checks before reporting a problem:

```powershell
pnpm test
pnpm typecheck
cargo test --workspace
```

## 3. Create your first project

1. Click **New project** on the welcome screen. The project creation wizard is full-screen,
   not a dialog over an empty scene. While no project is open, the welcome screen is the project
   hub: the Projects dialog is reserved for an open project, where it switches projects and
   exposes checkpoints and import/export.
2. Enter a project name, an optional project folder and choose a mode.

| Mode            | What you get                                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `Empty Project` | A blank world containing only air. Every block is placed by you or a tool.                                                     |
| `Flat base`     | An editable 33×33 platform around the origin. Choose its layers, bottom Y and biome; the backend validates them against the selected version's overworld height. Not vanilla terrain. |
| `Import World`  | A supported classic Java 1.21.4 world opened read-only, with a byte-for-byte source copy and an editable overlay.              |
| `Vanilla World` | An area generated by the official local Java 1.21.4 server after you verify Java, the server JAR and the EULA. See section 10. |

3. Continue to the **Version** step and confirm the exact Minecraft version. The catalog lists
   official releases and, behind a toggle, snapshots. Only versions with a verified profile show
   a support badge and can be created; the card shows Java, world height, layout, pack formats
   and every known limitation. Import reads the version from the world and asks only for
   confirmation.
4. On **Components**, prepare the exact-version client assets. Java is optional for editing and
   required for Vanilla World; the server is requested only for Vanilla. Each card offers a
   managed download, an already-installed component, or a manual file that is validated in
   place. Nothing is downloaded until you press a download button; the card shows the version,
   size, source host, checksum and status, and the download streams progress with Cancel.
   `Placeholder` is an explicit choice: it lets you edit with clearly marked placeholder
   textures, but it never claims a client JAR, checksum or block/item catalog. When a verified
   client JAR is ready, the step shows the catalog's block and item counts.
5. On **Source**, Empty has no parameters; Flat exposes the platform's layers, bottom Y and
   biome. Layers are written bottom-up, each 1–16 blocks thick up to the backend limit, and the
   whole source must stay inside the selected version's overworld height. Invalid layers are
   refused before the project is written.
6. Review the source, the resolved components and catalog, the conservative size/time estimate
   and every aggregated warning, then click **Create project** (or **Import world**). The
   **Preparing** screen lists the components that are already installed (they stay in the cache)
   and the real project stages: source analysis, editable blocks, metadata, source copy, verify
   and ready. A source copy shows byte progress. **Cancel preparation** stops the unpublished
   project at the next safe point and returns to Review without deleting downloads. If a stage
   fails, **Retry** repeats the same request and **Back to review** keeps every entered value.

Vanilla World uses `Basics → Version → Components → Source` and has no review step: creation
starts from its generation panel with **Open as project**. If that import fails, **Retry** uses
the completed run without generating it again. **Back to source** returns to the existing run.

A new project can be created only after its version has a verified profile and its Components
step is ready. A placeholder assets choice is accepted with a warning; it is never presented as
a verified catalog. Projects are stored as folders inside `Documents/FuryBuilder` (falling back
to the app-data directory when the documents folder is unavailable). Treat that folder as
application data: use the editor to rename, checkpoint and save, and do not hand-edit project
files while the app is running.

## 4. A tour of the window

```
┌──────────────────────────────────────────────────────────────────────┐
│ FuryBuilder  Project  View  AI / MCP    project · saved   Save  Search  ⚙ │
├──────────────┬───────────────────────────────────┬───────────────────┤
│ World panel  │          3D viewport              │ Inspector         │
│ dimensions   │  selection / ghost / grid         │ block + selection │
│ filter       │                                   │ project + paste   │
├──────────────┴───────────────────────────────────┴───────────────────┤
│ Blocks | Terrain | Heightmap | … | Analysis | Activity                   │
├──────────────────────────────────────────────────────────────────────┤
│ Core | project | dimension | job | rev | chunks | blocks | fps | DV  │
└──────────────────────────────────────────────────────────────────────┘
```

- **Toolbar.** `Project` opens the project dialog while a project is open, where it switches
  projects and exposes checkpoints and import/export. On the welcome screen it is disabled
  because the welcome screen and full-screen wizard own opening and creation. `View` toggles
  panels. `AI / MCP` sets agent access. Undo/redo, save, the project-state chip, the command
  palette and Settings are on the right. The top bar does not repeat the active palette block:
  the current block lives in the Inspector and Blocks tab. Core status lives only in the status
  bar. Save lives in the toolbar chip; the viewport performance panel reports rendering metrics
  and the last operation only.
- **World panel.** Switch the displayed dimension and filter the tree. The current alpha
  loads the overworld; the Nether and End are listed but not streamed yet.
- **Viewport.** The 3D scene, selection box, chunk borders, grid and the bottom input hint.
  Camera and editing controls are in section 5.
- **Inspector.** Shows the picked block and its properties, the current box selection, copy
  and paste controls, replace source, and project/runtime details.
- **Bottom panel.** Twelve tabs: `Blocks`, `Terrain`, `Heightmap`, `Biomes`, `Generators`,
  `Layers`, `Templates`, `Objects`, `Parametric`, `Build DSL`, `Analysis`, `Activity`.
  `Analysis` groups `Observation` and `Validation`; `Activity` groups `Console` and `History`.
  Your active tab and panel visibility are remembered between launches.
- **Status bar.** Backend state, project, dimension, active job or tool, revision, chunk and
  block counts, load radius, FPS/draw calls, target Minecraft version and `DataVersion`.

## 5. Move the camera and edit blocks

Camera (fly mode is the default):

| Input                     | Action                              |
| ------------------------- | ----------------------------------- |
| `W` / `A` / `S` / `D`     | Forward / left / back / right       |
| `Space` / `Ctrl` (or `C`) | Up / down                           |
| `Shift`                   | Faster movement                     |
| Right-drag                | Look around                         |
| Mouse wheel               | Change base speed                   |
| Double-click              | Pick a block and fly to it          |
| Right-click without drag  | Context menu for the block under it |

Tools use the number row (`1`–`8`):

| Key | Tool       | How it works                                                    |
| --- | ---------- | --------------------------------------------------------------- |
| `1` | Select     | Pick a block and inspect it.                                    |
| `2` | Place      | Place the palette block on the picked face.                     |
| `3` | Remove     | Replace the picked block with air.                              |
| `4` | Brush      | Place a small sphere; set the radius in the viewport toolbar.   |
| `5` | Box select | Click one corner, then the opposite corner.                     |
| `6` | Fill       | Fill the current box with the palette block.                    |
| `7` | Line       | Click a start and an end for a connected line.                  |
| `8` | Replace    | Replace one source state inside the box with the palette block. |

Tips:

- Choose the block in the **Blocks** tab first. `Alt`-click picks an existing world block as
  the current block.
- A selection is inclusive and may use negative coordinates. Volumes above 1,000,000 blocks
  are rejected before an operation is built.
- `Ctrl+Z` / `Ctrl+Shift+Z` (or `Ctrl+Y`) undo and redo through the Rust core. Every normal
  edit is one reversible operation.
- Typing in a search box, coordinate field or property editor never moves the camera or
  changes tools.

Other useful shortcuts:

| Shortcut            | Action                                                              |
| ------------------- | ------------------------------------------------------------------- |
| `Ctrl+K`            | Searchable command palette. A query like `12 64 -8` offers “Go to”. |
| `Ctrl+B`            | Toggle the world panel.                                             |
| `Ctrl+Alt+B`        | Toggle the Inspector.                                               |
| `Ctrl+J`            | Toggle the bottom panel.                                            |
| `Ctrl+S`            | Save the project.                                                   |
| `Ctrl+C` / `Ctrl+V` | Copy the box selection / paste at the target.                       |
| `Escape`            | Cancel a staged paste, then a running job, then the selection.      |

## 6. Save, close and recover

- The toolbar chip shows `Saved`, `Unsaved changes` or `Autosaved · unsaved`. The viewport
  performance panel reports rendering metrics and the last operation, not a second save state.
- **Autosave** runs every 30 seconds while edits are unsaved, and on window close. It is not
  a replacement for `Ctrl+S`.
- **Checkpoints** are full verified snapshots. Open `Project → Checkpoints`, write a reason
  and click **Create checkpoint**. Up to five are kept; restoring one replaces the open world
  after confirmation.
- Saves are atomic: a temporary file is decoded and re-encoded, hashed, published, and the
  manifest is updated. A failed save does not publish a half-written project.
- If the app closes unexpectedly, the next launch may show a **recovery banner**. A verified
  autosave is offered explicitly; a damaged autosave is reported and the last saved revision
  is opened instead. Nothing is silently presented as recovered.

## 7. Export a Java structure

The supported interchange format is Minecraft Java **structure `.nbt`** for 1.21.4
(`DataVersion` 4189).

1. Select a box (or use the whole loaded area when no selection exists, as shown by the
   preview).
2. Open `Project → Import / Export → Export structure`.
3. Choose the dimension and whether to use the current selection.
4. Click **Preview export**. Check size, volume, non-air blocks, target `DataVersion` and
   warnings.
5. Click **Export .nbt**. The file is written under the project's `exports` folder, re-read
   and compared before it is reported as verified.

Entities, block entities and unknown tags are refused rather than silently dropped. Sponge
`.schem` is not enabled. A structure export is not a full world save: it contains the blocks
in the chosen bounds, not `level.dat`, dimensions or sidecar data.

## 8. Import a structure

1. Open `Project → Import / Export → Import structure`.
2. Pick a Java `.nbt` file. FuryBuilder shows size, non-air/stored blocks, entities, block
   entities, target version and unknown tags before writing anything.
3. Choose **new project** or **insert into the open project**, then set the dimension and
   origin.
4. Confirm. An insert is one reversible operation and obeys layers, masks and protected
   regions.

Unsupported payloads are blocked at preview; the importer does not skip entities or unknown
data quietly.

## 9. Import an existing Java world

1. Open `Project → Create`, choose **Import World**, then pick **World folder** or
   **.zip archive**. A folder must contain `level.dat`; an archive may contain the world at
   its root or inside one wrapper folder.
2. Click **Analyze**. The wizard reports the version, layout, dimensions, region/chunk counts
   and a read/edit/write/passthrough support matrix, plus blockers. An archive is extracted
   to a temporary folder for the read-only check and removed afterwards.
3. Choose **Import as-is**. Conversion is shown as unavailable until a verified converter and
   target profile ship; the detected version is never silently changed or downgraded.
4. Click **Import world**. FuryBuilder copies the source byte for byte, keeps it immutable and
   opens an editable overlay.

Only classic Java 1.21.4 world layouts are supported. A single `.mca` file or a bare
`region/` directory is not a complete world and is refused. Archive entries are bounded and
traversal, absolute paths, symlinks, duplicate names and oversized entries are refused. Edits
are stored in the project overlay; the source folder or archive is never written. Untouched
chunk data, entities, block entities, heightmaps, light and POI are preserved as raw source
data rather than recalculated.

## 10. Generate a Vanilla World

This is the only mode that claims to use the original Minecraft generator, and it has real
prerequisites.

1. Open **New project** (or `Project → Create`) and choose `Vanilla World`. The wizard shows
   the verified generation target; a project that selects another version is refused instead
   of producing a mixed-version world.
2. Continue to **Version** and confirm the exact Minecraft version.
3. On **Components**, prepare the client assets, Java runtime and official server JAR for that
   version. Each card offers a managed download, an already-installed component or a manual
   file that is validated in place. Downloads show source, size and checksum; nothing is
   installed globally and nothing starts until the step is ready.
4. In the Source step choose a seed, preset, radius/center, structures, time limit and optional
   local data packs. The step reuses the Java runtime and server JAR verified in Components and
   never asks for them again. Before anything starts, the step shows the expected chunk count, a
   conservative world-size estimate, the free space on the run volume and the bounded time
   limit. Generation is disabled when the estimate does not fit; the backend repeats the same
   disk preflight before it creates a run directory.
5. Read and accept the Minecraft EULA for that exact server JAR and Minecraft version in the
   same step, then explicitly confirm the run. FuryBuilder never accepts the EULA for you, and
   another JAR or version needs its own acceptance.
6. Wait for the isolated server to generate the requested area. It runs without a game
   window, listens on loopback only and is terminated on cancel, failure or the time limit.
7. Click **Open as project** on the completed run. The generated folder becomes an immutable
   source copy with its seed, preset, data packs and Java/server identity recorded.
8. For a vanilla project, the project dialog can compare the saved generated base with the
   original generator's reference chunks. The check is bounded, applies only to an untouched
   revision-1 base and reports differences with coordinates. It is not a general guarantee
   that every edited configuration reproduces Minecraft.

`Vanilla World` requires Java 21 and the official server JAR; `Empty Project` does not.

## 11. Settings essentials

- **Appearance** — theme (dark/light/system) and UI scale.
- **Components** — an inventory of FuryBuilder-owned Java runtimes, client JARs and official
  server JARs, with version, size and cache path for each artifact. Verify re-checks an
  artifact against its recorded facts, Remove deletes only the cached copy after confirmation,
  and Open folder shows the cache root. Downloads, manual paths and placeholder choices are
  made in the project wizard, not here; Settings never provisions a project.
- **Updates** — manual check and verified install of a newer FuryBuilder build.
- **Diagnostics** — a bounded, path-redacted JSON Lines log with open-folder, refresh and
  clear actions. Clearing affects only `furybuilder*.log`.
- **Advanced** — backend status, application name and version.

Placeholder textures are an explicit mode, not an error and not a hidden fallback. The
viewport labels them, the palette stays on curated quick picks instead of the version catalog,
and block data is never changed. Selecting a client source replaces placeholder mode.

## 12. Quick troubleshooting

| Symptom                                 | What to check                                                                                     |
| --------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Editing and saving are disabled         | You are in browser preview (`pnpm dev`). Start `pnpm tauri:dev` and open a project.               |
| “No project open”                       | Create or open a project from **Project**.                                                        |
| `Core offline`                          | The Rust backend did not start; check the terminal running `pnpm tauri:dev`.                      |
| Textures are checkerboards              | Choose a verified client source in the project wizard's **Components** step.                     |
| Vanilla World is blocked                | The wizard's **Components** or **Source** step names the missing Java, server JAR or EULA step.    |
| Import is rejected                      | Only classic 1.21.4 world folders or `.zip` archives containing `level.dat` are supported.         |
| Structure export is blocked             | The `.nbt` adapter refuses entities, block entities or unknown tags instead of dropping them.     |
| A large paste only shows a pink preview | That is the staged path for pastes of 65,536+ non-air blocks. Press `Ctrl+V` again or confirm it. |
| Recovery banner after a crash           | Read the reason and choose whether to keep the verified autosave or discard it.                   |
