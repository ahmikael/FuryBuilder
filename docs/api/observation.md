# Observation contract (v0, M3)

Observation outputs are derived views of authoritative world data. They are revisioned,
bounded and explicit about completeness. The viewport capture is the first mode.

## Metadata

```ts
interface CaptureMetadata {
  schemaVersion: 1;
  mode: "viewport";
  dimension: string;              // "minecraft:overworld"
  worldRevision: number;          // Rust revision used for the snapshot
  camera: {
    position: [number, number, number];
    target: [number, number, number];
    yaw: number;
    pitch: number;
    fov: number;
  };
  resolution: [number, number];   // drawing-buffer pixels
  renderer: "three-webgl2";
  rendererSchema: 1;
  legend: Array<{ state: string; count: number; color: string }>;
  legendTruncated: boolean;
  requestedChunks: Array<{ x: number; z: number }>;
  loadedChunks: Array<{ x: number; z: number }>;
  missingChunks: Array<{ x: number; z: number }>;
  partial: boolean;
  capturedAt: string;             // ISO-8601
  notes: string[];
}
```

## Rules

- `worldRevision` is the revision of the snapshot the image was rendered from. An image
  is never presented as a live query of a newer revision.
- `partial = missingChunks.length > 0`. A partial image is still returned, but the caller
  must not treat it as a complete view of the requested area.
- `legend` is sorted by count (descending) and bounded to 16 states. `legendTruncated`
  reports that more states exist. Counts cover non-air blocks in loaded chunks, not the
  whole world.
- Colours in the legend are approximate placeholder-atlas averages for recognition, not
  sampled pixels.
- `requestedChunks` records the area that was asked for, independent of what was loaded.
- Extended modes (`top_down`, `heightmap`, `material_map`, `biome_map`, `cross_section`,
  `revision_diff`) are added after the viewport mode and must reuse the same envelope.

## Reproducibility

The same project, `worldRevision`, camera pose, resolution and renderer schema describe
the same view. Textures are original placeholders; replacing the asset source can change
appearance without changing block data. GPU anti-aliasing, driver differences and floating
point rasterization are explicitly outside the guarantee. `notes` repeats these caveats
for clients that only receive the image.

## Image and privacy

- The image is a PNG data URL generated by the local renderer. It contains no UI chrome,
  no filesystem paths and no account data.
- Metadata contains only world/camera information; it never includes secrets.
- MCP exposure of captures is added in the bridge milestone and remains bounded by the
  same policy layer as other observations.
