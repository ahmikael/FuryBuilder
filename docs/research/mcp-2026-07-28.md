# MCP 2026-07-28: capabilities, SDK and fallbacks

Status: researched 2026-11-17. Sources: MCP specification 2026-07-28, MCP blog release
notes, TypeScript SDK v2 docs, Tasks/Apps extension specs (per master plan §22).

## Protocol facts used by FuryBuilder

- The **core is stateless**. Project/selection/job identity is passed explicitly in tool
  arguments and resources. No implicit transport session owns editor state.
- Transport for the desktop bridge is **stdio**; the bridge is launched by the AI client.
  Streamable HTTP is a later, loopback-only, origin-checked option.
- **Capability negotiation** is mandatory: clients may not support Tasks, Apps or newer
  lifecycle details.
- **Tasks extension** (`io.modelcontextprotocol/tasks`) models long-running work. If the
  client advertises it, FuryBuilder may wrap internal jobs; otherwise ordinary
  `start_job`/`get_job_status`/`cancel_job` tools remain available.
- **Apps extension** (`ui://`) is optional presentation. Screenshots and structured
  resources are the required fallback.
- Multi round-trip requests/approvals are handled by returning a pending approval result
  and enforcing approval in the Core policy layer; an AI message never grants permission.

## SDK

- Official TypeScript SDK **v2**, npm package `@modelcontextprotocol/server` (verified
  available: 2.4.0). The bridge pins the version in its lockfile.
- The bridge contains only protocol mapping, schema validation and transport. All world
  logic stays in Rust.
- Server instructions/resources document supported protocol versions and capabilities.

## Client compatibility plan

| Client | Expected | Verification |
|---|---|---|
| OpenCode | stdio, standard tools | required real-client test (M7) |
| Claude Desktop / other MCP clients | stdio, standard tools | manual, documented |
| Clients without Tasks | start/status/cancel tools | automated contract test |
| Clients without Apps | images/resources | automated contract test |

## Consequences for tool design

- Every mutating tool takes `project_id` and an `idempotency_key`; revision-sensitive
  calls take `expected_revision`.
- Long operations return `job_id` immediately; polling is explicit and cancellable.
- Responses are bounded (`limit`, region size, image resolution) and declare `partial`.
- Tool schemas are generated/validated against the shared contract and never rely on
  hidden session state.
