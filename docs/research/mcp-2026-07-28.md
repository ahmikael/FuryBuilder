# MCP 2026-07-28: capabilities, SDK and fallbacks

Status: historical research snapshot, verified **2026-11-18** against the npm registry,
the official MCP specification changelog, the MCP TypeScript SDK v2 documentation and the
installed OpenCode client. The implementation has since moved to the official Rust SDK
(`rmcp` 3.11); see [ADR-017](../adr/ADR-017-mcp-rust-bridge.md). Protocol facts below still
apply, while package-specific guidance describes the former TypeScript bridge.

## Protocol facts used by FuryBuilder

- **The 2026-07-28 era is stateless.** There is no `initialize` handshake and
  no protocol-level session. Every request carries its protocol version and
  client capabilities in the `_meta` envelope
  (`io.modelcontextprotocol/protocolVersion`,
  `io.modelcontextprotocol/clientCapabilities`); servers advertise themselves
  through `server/discover`. Project, selection and job identity is therefore
  always an explicit argument, never implicit transport state.
- **Revisions before 2026-07-28 remain a separate legacy era.** The SDK serves
  both eras from one factory, but a connection's era is fixed at connect time.
  FuryBuilder must report which era a client negotiated instead of assuming
  modern support.
- **Transport for the desktop bridge is stdio**, launched by the AI client.
  The bridge must write JSON-RPC only to stdout and diagnostics to stderr.
  Streamable HTTP remains a later, loopback-only, origin-checked option.
- **Capability negotiation is mandatory.** Clients may not support Tasks, Apps
  or newer lifecycle details. Tools must remain usable without optional
  extensions.
- **Tasks moved out of the core protocol.** The 2025-11-25 task wire vocabulary
  is deprecated in SDK v2. The 2026-07-28 Tasks extension
  (`io.modelcontextprotocol/tasks`, SEP-2663) uses polling with `tasks/get`, a
  new `tasks/update`, and `tasks/cancel`; `tasks/result` and `tasks/list` are
  removed. FuryBuilder may use it only after negotiation and otherwise exposes
  ordinary `start_job` / `get_job_status` / `cancel_job` tools over its own Job
  API.
- **Apps extension** (`ui://`) is optional presentation. Screenshots and
  structured resources are the required fallback.
- **Multi round-trip requests** replace server-initiated sampling, roots and
  elicitation. An approval requested this way is still enforced by the Core
  policy layer; an AI message never grants permission.

Implementation facts from the v2 documentation:

- The server stdio entry is `serveStdio(factory)` from
  `@modelcontextprotocol/server/stdio`; it owns the transport and builds one
  server instance per connection.
- `serveStdio` serves older clients from the same factory by default. Modern
  negotiation uses `server/discover`; `legacy: 'reject'` can refuse 2025-era
  openings once FuryBuilder deliberately requires the modern era.
- A hand-built server or client keeps speaking the 2025-era protocol unless
  modern behaviour is explicitly selected. The bridge must opt in and test the
  negotiated era rather than assuming a package version changes the wire.
- `StdioServerHandle.close()` and stdin EOF are the supported shutdown paths.
- `npx @modelcontextprotocol/inspector <command>` is the first local diagnostic
  client; it does not replace the required real-client test.

## Consequences for bridge design

- Pin `@modelcontextprotocol/server` in the bridge lockfile; do not float on a
  major line. Keep protocol mapping in the TypeScript bridge and world logic in
  Rust.
- Use `serveStdio(factory)` with explicit modern-era behaviour and a tested
  legacy fallback. Never claim Tasks or Apps without negotiated capabilities.
- Every mutating tool takes `project_id` and `idempotency_key`;
  revision-sensitive calls take `expected_revision`. Responses are bounded and
  declare `partial` where data is incomplete.
- Do not log tokens, local socket names or private paths; stdout is reserved
  for protocol frames.
