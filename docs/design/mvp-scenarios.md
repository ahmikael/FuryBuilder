# MVP scenarios and acceptance criteria

Status: accepted for M0. Each scenario is a release gate for the first usable editor.

## Project modes (phased)

| Mode | Scope | Phase |
|---|---|---|
| **Empty Project** | Sparse 3D space or optional flat base; manual/AI building; no Java world required | MVP (M1–M6) |
| **Vanilla World** | Real Minecraft Java chunks from an explicit version + seed + preset, generated by the original Java engine | After MVP (M9) |
| **Import World** | Existing Java save opened read-only with copy-on-write overlay, new export copy | After MVP (M8) |

All modes share one Rust World Core, one Operation API, one undo/redo system, the same
renderer and the same project/export infrastructure.

## MVP-01 — First block (Empty Project)

Create an empty project for 1.21.4, choose `minecraft:stone_bricks`, place a block,
read the same block back through the Rust query API, undo and redo.

**Acceptance:** block coordinates and properties match between UI, Rust and MCP;
`world_revision` changes exactly once per applied transaction; undo restores the previous
state; `cargo test` covers the same operation.

## MVP-02 — Area build

Select a cuboid, preview a fill, apply it, replace blocks by predicate and undo the whole
batch atomically.

**Acceptance:** preview reports the exact affected block count; applying over limits is
rejected with a structured error; no partial write is visible after a rejected batch;
undo returns to the byte-identical palette/state set.

## MVP-03 — Chunk boundaries

Build a bridge across X=15/16 and Z=-1/0.

**Acceptance:** negative coordinates use floor division; no missing/duplicated blocks at
section or chunk borders; neighboring chunk meshes rebuild after edits.

## MVP-04 — Persistence and recovery

Build, save, close, reopen; kill the process during a save and reopen again.

**Acceptance:** semantic equality after reopen (blocks, biomes, metadata, revision);
autosave checkpoint survives a crash; corrupted/incomplete temp files are never
published as a valid project.

## MVP-05 — Safe export

Export a bounded structure into the declared first format and re-import it.

**Acceptance:** the file is a valid 1.21.4 NBT structure, block states and orientation
survive, supported block entities are preserved, unsupported data is reported, and the
export never claims success for a partially written file.

## MVP-06 — MCP agent loop

Connect an external MCP client read-only, then enable edits for a bounded selection.
Inspect the world, preview and apply a batch, capture a bounded screenshot, undo.

**Acceptance:** read-only mode rejects writes at the Core policy layer; out-of-selection
edits are rejected; every operation is auditable with actor/operation/revision; a missing
Tasks/Apps capability still allows the basic start/status/cancel loop.

## Out of scope for MVP

Full Anvil write support for arbitrary worlds, vanilla parity from a hand-written
generator, Bedrock formats, servers, multiplayer and marketplace features.
