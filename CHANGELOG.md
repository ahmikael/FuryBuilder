# Changelog

All notable user-visible changes to FuryBuilder are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the application follows
[Semantic Versioning](https://semver.org/). The application version is independent from the
project schema, the world snapshot format and the MCP tool schema; see
[docs/release/versioning.md](docs/release/versioning.md).

## [Unreleased]

### Added

- Verified Windows NSIS installer flow: clean per-user install, application startup,
  0.1.0 → 0.1.1 update with user-data preservation, and uninstall that keeps projects.
- MSI package integrity check by administrative extraction. A per-machine MSI install still
  requires an elevated session and is documented as untested by the non-elevated harness.
- Single-source application version in `version.json` with `pnpm version:check` and
  `pnpm version:set`; CI rejects drifting manifests.
- Release versioning, migration and backup policies under `docs/release/`.
- Dependency security and license audit: `cargo audit`, `pnpm audit`, a generated
  third-party inventory, `pnpm licenses:check` in CI, and `scripts/verify-release-artifacts.ps1`
  for installer hashes, versions and Authenticode status.
- Bundled self-authored demo project (`examples/furybuilder-demo.furybuilder`), real WebView2
  screenshots, a deterministic observation map and a recorded read-only MCP probe in
  `docs/demo/`. The demo contains no Mojang assets and opens without Minecraft or Java.
- Release-level import/export verification against the official 1.21.4 server: server-generated
  normal world → real app import/edit/save/reopen → complete world export → server block checks
  → app re-import of the server-saved world. The recorded run and limits are in
  `docs/testing/java-server-interop.md`.
- Isolated clean-user setup check: Empty Project without Java/Minecraft, explicit Vanilla
  dependencies, a consentless-run rejection, offline metadata failure, launcher-root
  discovery, and damaged/stale Java and server cache rejection. The recorded run and the
  remaining clean-VM gap are in `docs/testing/clean-setup.md`.
- Tag-driven Windows release workflow: pushing `v<version>` validates the tag against
  `version.json`, builds NSIS/MSI packages and signed updater artifacts, publishes
  `latest.json`, appends SHA-256 checksums and creates the GitHub release.
- Conventional-commit release notes generated by `scripts/release-notes.mjs`, with
  breaking changes separated and internal `chore`/`test`/`ci`/`build`/`style` commits
  omitted.
- Built-in Tauri auto-updater: installed builds check GitHub Releases after startup, show a
  non-blocking update banner and Settings controls, verify the matching signed installer
  before installation and preserve projects/settings. Authenticode signing remains a
  separate external release gate.

### Changed

- Viewport capture metadata now names its texture source (`placeholder` or
  `minecraft_assets`) instead of always claiming placeholder textures.
- Upgraded `zip` from 2.6.1 to 9.7.3 to fix six RustSec advisories
  (RUSTSEC-2026-0367/0368/0369/0429/0545/0548).
- Raised the minimum supported Rust version to 1.88, as required by `zip 9.7.3`.
- Raised the minimum supported Rust version to 1.90, as required by the Tauri updater and
  process plugins.
- Project schema migration now copies the original `project.json` byte for byte before
  applying the migration, instead of writing a rewritten document as the backup.
- Per-save `project.json.bak-*` copies are now bounded to the newest five revisions.
- Managed Java/server metadata and download requests honor the standard
  `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` environment variables. Checksums are still verified;
  a broken proxy produces an explicit network error instead of a silent fallback.

### Fixed

- A failed migration or interrupted save can no longer leave an unbounded pile of manifest
  backups or a non-verbatim migration backup.
- Block counts in operation labels and editor previews now use deterministic `en-US`
  grouping instead of the host locale, keeping history text and CI expectations stable.

### Security

- Removed six known `zip` extraction advisories by upgrading to `zip 9.7.3`; the runtime
  extractor keeps its own path, symlink, entry-count and size checks.
- Added a repeatable dependency/license audit and an Authenticode verification gate. Beta
  installers remain unsigned until an external code-signing certificate and key exist.

## [0.1.0] - 2026-11-19

First beta baseline, developed through milestones M0–M10 and the first M11 release tasks.

### Added

- Windows desktop editor for Minecraft Java Edition 1.21.4 (`DataVersion` 4189) built on
  Tauri 2, React, TypeScript, Three.js and a Rust world core.
- Empty and flat projects, read-only analysis and safe copy-on-write import of classic
  1.21.4 worlds, and Vanilla World generation through the official local Java server engine.
- Sparse chunk editing, selection tools, terrain brushes, biome tools, layers, masks,
  templates, semantic objects, a typed Build DSL, deterministic observation maps and
  validation findings.
- Undo/redo, autosave, checkpoints, crash recovery and an eight-snapshot project history
  with the previous manifest retained on every save.
- Java structure `.nbt` round-trip, complete world-folder export with byte-preserving
  passthrough, and official-server import/export smoke tests.
- Local Minecraft asset discovery, verified client-version matching, ordered resource packs
  and a documented placeholder fallback.
- Managed Java runtime and official `server.jar` provisioning with explicit consent,
  checksum verification, offline cache and isolated generation processes.
- MCP stdio bridge over the same application API as the UI, with read-only default,
  scoped writes, previews, confirmations, jobs, screenshots and observation tools.
- Windows graphics-path stress evidence, cache budgets, diagnostics and beginner/advanced
  documentation.

### Security

- Imported files, resource packs, worlds and MCP calls are bounded and fail closed.
- FuryBuilder distributes no Mojang JARs, assets or game binaries; downloads happen only
  after user action and are verified against official metadata.
